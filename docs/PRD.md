# 孕期记录本地应用方案

## 1. 要解决什么

怎么在没有服务器、没有域名的情况下，在一台 iPhone 里按「每一次产检」把孕周、预产期、医生开的检查单、检查结果、这次花了多少钱，以及这个阶段该注意的事记在一起，并且换手机、清掉应用也不会丢。

记录和查看都在这一个应用里完成。你和你媳妇共用这一台手机，不做第二台同步。

这不是一个要上架的孕期社区，也不是一套医疗建议系统。它是你们两个人自己用的病历加账本。

## 2. 谁用、怎么算成功

| 项 | 定法 |
| --- | --- |
| 使用者 | 你和你媳妇共用一台手机。谁拿着都能记，也都能看 |
| 设备 | 只用一台 iPhone。不做第二台手机的同步和互传 |
| 成功 | 医院里没网也能记下一次产检；同一个应用里能看到今天孕几周、下次产检、一共花了多少；检查单照片和费用都挂在对应的那次产检上；导出的备份以后导入回来，记录、金额、照片都还在 |

## 3. 推荐做法

做一个装在这一台 iPhone 主屏幕上的本地应用（PWA）。

- 没有服务器，没有域名，没有注册和登录。
- 记录、金额、检查单照片只存在这一台手机里。
- 医院没有 Wi-Fi 也能打开、能记、能改、能查。
- 不上架 App Store。苹果开发者账号每年要钱，审核也慢，一台手机自己用不值得。

安装方式：用 Safari 打开应用，选「添加到主屏幕」。之后图标像普通 App 一样点开，不依赖电脑一直开着。第一次装的时候，电脑和手机在同一个 Wi-Fi 下打开一次即可。

备份不是以后再补的功能。数据在手机里，清掉网站数据、换手机、手机丢了就会没。第一版就要能导出、导入，首页会提醒多久没备份。备份文件存到电脑或 U 盘，用来防丢，不是给第二台手机同步。

### 3.1 技术选型

| 项 | 选择 | 理由 |
| --- | --- | --- |
| 前端框架 | Vue 3 + Vite | 轻量、Safari PWA 兼容性好、单文件组件便于维护；比纯 HTML+JS 更适合多页签交互，比 React 更轻 |
| 本地存储 | IndexedDB（通过 idb-keyval 或 Dexie） | 支持二进制照片存储，容量远大于 localStorage；Safari 对 IndexedDB 支持稳定 |
| 离线缓存 | Service Worker + Cache API | 首次加载后缓存全部静态资源，断网仍可打开和操作 |
| 照片压缩 | Canvas API 客户端压缩 | 长边 ≤ 1600px，JPEG quality 0.8；不依赖后端 |
| 备份格式 | ZIP（JSON 数据 + 独立图片文件） | 体积小、结构清晰；解压后可单独查看图片；比 base64 嵌入 JSON 更高效 |
| PIN 锁屏 | SHA-256 哈希校验，默认关闭 | 四位数字仅防随手翻；开启时明确提示安全性有限 |
| 构建产物 | 纯静态文件（HTML/CSS/JS） | 无需 Node 运行时，任意静态服务器或直接 file:// 均可部署 |

## 4. 为什么不用别的做法

| 做法 | 结论 |
| --- | --- |
| 一台手机上的本地应用，数据在本机，导出备份文件 | 用这个。符合没有服务器、只用一台 iPhone、病历不想上传的条件 |
| 备忘录、相册、Excel | 能记一些，但孕周、一次产检里的单子、照片和花费对不上，医院里也不好翻 |
| 微信小程序 | 不做。要企业主体和服务器，数据也不在你自己手里 |
| 自己租云服务器 | 不做。要管域名、证书、备份、账号，丢数据的风险比本地大 |
| 上架成正式 App | 不做。苹果开发者账号每年 99 美元，审核周期长，一台手机自己用不划算 |
| 第二台手机同步或隔空投送互看 | 不做。你们就在这一台手机上记和看 |

## 5. 打开之后长什么样

手机竖屏，字大一点，医院里单手能点。界面用简体中文。

底部五个页签：首页、产检、花费、阶段、我的。

### 5.1 首页

只回答四件事：

- 今天孕几周几天，预产期哪天，还剩多少天，现在是早、中、晚哪个阶段
- 下次产检是哪天。只在打开应用时显示，不做系统推送
- 一共花了多少，这个月花了多少
- 最近一次产检，以及备份提醒（距上次导出 > 7 天 OR 新增 ≥ 3 条产检记录时显示温和提示）

还没建立孕期时，首页只有一件事：填末次月经、当前孕周，或者直接填医院给的预产期。

### 5.2 产检

每一次产检一条，按日期倒序。进去之后看到这次的全部：

- 日期、医院、科室、医生、当天自动算出的孕周
- 这次来做什么，医生怎么说，自己的备注
- 下次预约日期
- 这次开的检查单
- 这次的花费

一张检查单包含：项目名、开单说明、做没做、结果文字、拍的照片。照片可以是检查单、化验单、B 超图、收费单。

改预产期不会把旧记录的孕周重算乱。每次产检保存当天的孕周。

### 5.3 花费

两种：

- 挂在某次产检上的：挂号、检查、药品、其他
- 单独的用品：孕妇枕、待产包、衣服、营养品、其他

页面看总计、按分类、按月。金额用元，保留两位小数。不做成完整记账软件，不做预算、账户、多币种。

### 5.4 阶段

按当前孕周显示常见产检节点和注意事项，当成备忘，不当成诊疗意见。以你们医院的医嘱为准。

每一条可以标成「我们医院不查这个」或「已经做了」。应用不解读化验单，不判断正常还是异常。

**内容可编辑**：预置国内常见节奏作为初始内容，用户可以在 App 内自行添加、修改、删除条目。自定义条目与预置条目数据结构一致，导出备份时一并包含。标记为「本院不查」的条目灰显但不隐藏，方便以后恢复。

阶段按国内常见节奏写进应用，不联网查。范围如下，具体周数以产科常规为参考，不替代医生安排：

| 阶段 | 孕周 | 常见内容 |
| --- | --- | --- |
| 孕早期 | 不满 14 周 | 确认宫内孕、建档、基础化验、NT、早孕反应和禁忌 |
| 孕中期 | 14 周到不满 28 周 | 唐筛或无创、大排畸、血常规、胎动、营养 |
| 孕晚期 | 28 周及以后 | 糖耐、产检加密、胎心监护、待产包、临产信号 |

### 5.5 我的

- 孕期资料：姓名或昵称、末次月经、预产期来源、医院校正后的预产期
- 导出备份、导入备份
- 四位数字锁屏，**默认关闭**。开启时提示"仅防随手翻阅，不防技术破解"
- 清空本机数据前必须先确认，并提示先备份

## 6. 预产期怎么算

建立孕期时三选一。算完都可以改成医院写在本子上的那一天，之后以医院的为准。

| 方式 | 算法 |
| --- | --- |
| 末次月经第一天 | 加 280 天 |
| 只知道今天大约第几周几天 | 用今天的日期倒推末次月经，再加 280 天 |
| 医院已经给了预产期 | 直接用这一天，再反推今天第几周 |

规则：

- 孕 0 周第 0 天等于末次月经第一天。
- 早期 B 超校正过的日期，优先于自己按月经算的。
- 改预产期时，以前产检上已经写下的孕周不变。
- 今天的孕周每次打开都按当前预产期重新显示。
- 日期按手机当地日历计算，不跨时区换算。

## 7. 数据放哪

全部在这一台 iPhone 的本地存储里，不上传。

一份备份是一个 ZIP 文件，里面包含 JSON 数据文件和独立的图片文件。导出后存到电脑或 U 盘。这个文件等于病历加账单，不要发到公开链接里，也不要随手转发给别人。ZIP 格式比 base64 嵌入 JSON 体积更小，解压后可单独查看图片。

导入时覆盖这一台手机上的现有记录。导入前先提示会替换，并要求确认。导入是为了换机或误删之后找回来，不是给另一台手机同步。

照片存进应用前压缩，长边不超过 1600 像素，JPEG quality 0.8。拍照后自动校正旋转方向。多张照片上传时显示进度条。存储空间不足时提示并阻止新增照片。查看照片支持双指缩放和全屏浏览。原图仍建议留在系统相册里。

四位数字锁**默认关闭**。开启时明确提示安全性有限（仅 10000 种组合）。密码只保存 SHA-256 校验值，不保存明文。它挡不住懂技术的人。真正的保护是备份文件别外传。

数据里有这些东西：

- 一份孕期档案：昵称、末次月经、预产期、预产期是怎么来的、是否被医院日期覆盖
- 多次产检：日期、医院、科室、医生、当天孕周、就诊目的、医嘱、备注、下次预约
- 每次产检下的多张检查单：名称、说明、状态、结果文字、照片
- 多笔花费：金额、日期、分类、备注，以及它属于哪次产检；用品花费不属于任何一次产检
- 阶段备忘的勾选状态、用户自定义条目
- 锁屏是否开启（默认关闭）。密码只保存 SHA-256 校验值，不保存明文

## 8. 第一版做这些

| 编号 | 功能 | 必须能验证 |
| --- | --- | --- |
| F1 | 建立孕期 | 三种算法都能得到预产期和今天孕周；可以改成医院日期 |
| F2 | 首页 | 显示孕周、倒计时、下次产检、花费合计、备份提醒 |
| F3 | 产检记录 | 能新增、修改、删除；挂检查单、结果文字、照片、这次的费用 |
| F4 | 花费 | 产检费用和用品费用分开；能看总计、分类、按月 |
| F5 | 阶段备忘 | 按当前孕周显示；可勾选已做或本院不查；可自行添加/修改/删除条目 |
| F6 | 备份 | 导出的文件再导入回这一台手机，记录、金额、照片都还在 |
| F7 | 锁屏 | 默认关闭；开启后重新打开要输密码；密码错了进不去；连续错 5 次锁定 60 秒；可以关闭 |

预产期、孕周、金额合计要有可重复跑的计算检查，不靠肉眼对数字。

## 9. 第一版不做

| 不做 | 原因 |
| --- | --- |
| 注册、登录、云同步 | 没有服务器，也不该把病历交给别人 |
| 第二台手机同步、隔空投送互看 | 你们就在这一台手机上记和看 |
| 解读报告、判断指标正常异常 | 这是医生的事。应用只原样保存 |
| 系统推送、提醒闹钟 | iPhone 主屏幕应用做不到可靠的后台推送。打开就能看到下次产检 |
| 社区、商城、待产包种草 | 和记录无关 |
| 完整记账、预算、多账户 | 只要产检花费和用品花费 |
| 上架 App Store | 账号费用和审核成本高于使用价值 |
| 多个孕期、多个宝宝分开记 | 当前只有这一次孕期。以后真要再记，先导出这一份再清空 |

## 10. 默认已经这么定

这些不再单独确认。和实际用法不一致时再改方案。

- 你和你媳妇共用一台手机，记录和查看都在这一个应用里。
- 预产期以医院为准，自己算的只是起点。
- 只用一台 iPhone，用主屏幕应用，不上架。
- 界面简体中文，手机竖屏优先。
- 照片压缩后存进应用，原图留在相册。
- 阶段文字是普通备忘，页面上写明不替代医生。

## 11. 做之前还要知道的风险

- 主屏幕应用的数据在这一台手机的网站数据里。系统不会帮你备份它。不导出就可能丢。
- iPhone 低电量模式或长时不打开，浏览器可能清掉这份数据。所以每次重要产检后要导出一次，存到电脑或 U 盘。
- 备份文件如果发错人，对方就拿到了完整病历和账单。
- 四位锁忘了无法找回。忘记时只能清掉应用数据。有备份就能导入回来。
- 阶段备忘可能和你们医院的实际安排不一样。以医院为准，不一致的条目标成「本院不查」。

### 11.1 已知异常场景清单

| 场景 | 处理方式 |
| --- | --- |
| 导入损坏/格式错误的备份文件 | 校验 ZIP 结构和 JSON schema；失败时提示具体原因，不覆盖现有数据 |
| 存储空间不足 | 新增照片前检查剩余空间；不足时提示并阻止写入，建议先导出备份再清理旧照片 |
| 预产期输入非法日期 | 限制范围：末次月经不早于今天 -300 天、不晚于今天；预产期不早于今天 +140 天、不晚于今天 +300 天；超出范围即时提示 |
| 删除产检记录 | 二次确认弹窗，明确列出将同时删除的检查单、照片和关联费用；确认后级联删除 |
| 删除单张检查单/照片 | 二次确认；仅删除该条目，不影响同次产检的其他内容 |
| PIN 连续输错 5 次 | 锁定 60 秒，防止暴力尝试；倒计时结束后重置计数 |
| Service Worker 缓存失效 | 检测到版本更新时静默刷新缓存；离线状态下仍使用旧缓存，不阻断操作 |
| 照片压缩失败（如 HEIC 不支持） | 回退到原图存储并提示体积较大；Safari iOS 17+ 已支持 HEIC 解码 |

## 12. 做出来之后怎么用

1. 电脑和这一台 iPhone 连同一个 Wi-Fi。
2. 电脑打开应用，手机 Safari 访问电脑显示的地址。
3. Safari 里选分享，再选添加到主屏幕。
4. 以后只点主屏幕图标。电脑可以关掉。
5. 建好孕期后，每次产检回来在这一个应用里记一条，随手导出备份存到电脑或 U 盘。
